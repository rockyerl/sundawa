# Contributing and governance

- Skill descriptions must say **what** and **when**; name matches the directory and uses kebab-case.
- Add test methods/evidence and avoid vague instructions such as "ensure best practices" without verification.
- Keep ISO/OWASP registry pinned by version, verify links and mark source access requirements.
- Never commit secret-bearing evidence or real client files.
- All proposed changes need engineering/QA/security review matching the domain.
- Changes to schema must migrate examples, validators and CI tests.
- Release gate thresholds require sign-off from engineering and risk owner.
